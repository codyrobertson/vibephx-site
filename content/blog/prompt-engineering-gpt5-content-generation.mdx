# Prompt Engineering for GPT-5: How We Generate Production-Quality Content at Scale

We built an AI content engine that generates **100+ articles, guides, and newsletters per day** using GPT-5. The content is good enough to publish with **minimal editing**.

This isn't magic. It's **prompt engineering**.

Here's every technique, prompt template, and quality control we use to make GPT-5 produce content that doesn't suck.

## The Challenge: Generic AI Content Sucks

Early experiments with GPT-4 produced content that was:
- **Generic**: "AI is transforming industries..." 🥱
- **Shallow**: No technical depth, just surface-level fluff
- **Repetitive**: Same structure for every article
- **Inaccurate**: Hallucinated facts and outdated info
- **Boring**: No personality, no examples, no humor

We needed content that was:
- **Specific**: Real code examples, concrete use cases
- **Deep**: Technical explanations that developers respect
- **Varied**: Different structures, tones, and approaches
- **Accurate**: Verifiable claims with sources
- **Engaging**: Conversational tone, real-world stories

The solution? **Prompt engineering**.

## Phase 1: Research with Exa

### The Prompt

```typescript
const researchPrompt = `
You are a technical researcher analyzing content about ${topic}.

Your task:
1. Review the provided search results from Exa
2. Extract key technical claims, statistics, and code patterns
3. Identify the most recent and authoritative sources
4. Rate your confidence in each claim (0-100)

Search Results:
${exaResults.map(r => `
Title: ${r.title}
URL: ${r.url}
Published: ${r.publishedDate}
Content: ${r.text}
`).join('\n\n')}

Output format (JSON):
{
  "claims": [
    {
      "claim": "Next.js 15 introduces Turbopack for 10x faster builds",
      "source": "https://nextjs.org/blog/next-15",
      "confidence": 95,
      "category": "performance"
    }
  ],
  "codeExamples": [
    {
      "language": "typescript",
      "code": "...",
      "description": "...",
      "source": "..."
    }
  ],
  "statistics": [
    {
      "metric": "Build time reduction",
      "value": "10x faster",
      "source": "...",
      "confidence": 90
    }
  ],
  "overallConfidence": 85
}

Only include claims with confidence >= 70. Prioritize recent sources (2024-2025).
`
```

### Key Techniques

**1. Structured JSON Output**
- Forces GPT-5 to organize data consistently
- Easy to parse and validate
- Prevents rambling prose

**2. Confidence Scoring**
- GPT-5 rates its own certainty (0-100)
- Filter out low-confidence claims (< 70)
- Prioritize high-confidence data in final article

**3. Source Attribution**
- Every claim must include a URL
- Prevents hallucinations (GPT-5 can't cite fake sources)
- Allows human verification

**4. Date Filtering**
- Explicitly request recent sources (2024-2025)
- Reduces outdated information
- Ensures relevance

## Phase 2: Outline Generation

### The Prompt

```typescript
const outlinePrompt = `
You are a technical content architect creating an outline for: "${title}"

Research data:
${JSON.stringify(researchData, null, 2)}

Create a detailed outline with:
1. Introduction (hook + context)
2. 4-6 main sections (each with 2-4 subsections)
3. Code examples placement
4. Conclusion with actionable takeaways

Requirements:
- Use conversational dev-to-dev tone
- Include specific code examples (not "example here")
- Reference real statistics from research
- Vary structure (not every article starts with "Introduction to...")
- Add personality (humor, hot takes, real-world stories)

Output format (JSON):
{
  "title": "The actual title",
  "hook": "Opening sentence that grabs attention",
  "sections": [
    {
      "title": "Section Title",
      "subsections": [
        {
          "title": "Subsection Title",
          "keyPoints": ["Point 1", "Point 2"],
          "codeExample": "Brief description of code to include"
        }
      ]
    }
  ],
  "conclusion": {
    "summary": "1-2 sentence summary",
    "takeaways": ["Actionable takeaway 1", "Actionable takeaway 2"]
  }
}
`
```

### Key Techniques

**1. Hook First**
- Force GPT-5 to create a compelling opening
- Reject generic intros ("In this article, we'll explore...")
- Examples:
  - ✅ "We had a problem. Our build times hit 5 minutes."
  - ❌ "Next.js is a popular React framework..."

**2. Structural Variety**
- Explicitly request different structures
- Problem → Solution format
- Story-driven narratives
- Tutorial-style walkthroughs
- Debugging case studies

**3. Specific Code Placement**
- Don't just say "include code example"
- Specify WHAT code and WHERE
- "Show the actual API route code with error handling"

**4. Personality Injection**
- Request humor, hot takes, real stories
- "No bullshit" tone
- Conversational language ("We built X, then it broke. Here's why.")

## Phase 3: Draft Generation

### The Prompt

```typescript
const draftPrompt = `
You are a senior software engineer writing a technical blog post.

Title: ${outline.title}
Outline: ${JSON.stringify(outline, null, 2)}
Research: ${JSON.stringify(researchData, null, 2)}

Write a 3000-5000 word article following this outline.

TONE REQUIREMENTS:
- Conversational dev-to-dev (not marketing copy)
- Use "we" not "I" (team voice)
- Real code examples (not pseudocode)
- Specific metrics (not "much faster", say "60% faster")
- No fluff or filler
- Humor is good, cringe is not

TECHNICAL REQUIREMENTS:
- All code must be syntactically correct
- Include error handling in examples
- Show both "before" and "after" when refactoring
- Explain WHY not just WHAT
- Link to official docs for verification

STRUCTURE REQUIREMENTS:
- Start with the hook (not "Introduction" heading)
- Use ## for main sections, ### for subsections
- Include code blocks with language annotations
- Add inline comments for complex code
- End with actionable takeaways (checklist format)

BAD EXAMPLES TO AVOID:
❌ "In this article, we'll explore..."
❌ "Let's dive into..."
❌ "As you can see from the example above..."
❌ Generic code like "const data = fetchData()"

GOOD EXAMPLES TO FOLLOW:
✅ "We had a problem. Our API was timing out."
✅ Direct code with real function names and error handling
✅ Specific metrics: "Reduced API latency from 850ms to 120ms"

Write the full article now. Use markdown formatting.
`
```

### Key Techniques

**1. Tone Enforcement**
- Explicit "bad examples" section
- Show what NOT to do
- GPT-5 learns by negative examples

**2. Code Quality Standards**
- "Syntactically correct" (not pseudocode)
- Error handling required
- Before/after comparisons

**3. Specificity Mandate**
- Reject vague language ("faster", "better")
- Require metrics ("60% faster", "reduced by 200ms")
- Real function/variable names (not `foo`, `bar`)

**4. Format Constraints**
- Markdown headings enforced
- Code blocks with language tags
- Checklist format for takeaways

### 2. Negative Examples

Show what NOT to do:

```typescript

BAD EXAMPLE (don't write like this):
"In this article, we'll explore the fascinating world of Next.js..."

GOOD EXAMPLE (write like this):

`
```

**Result**: Fewer generic intros.

### 3. Self-Critique Loop

Make GPT-5 review its own output:

```typescript
// Step 1: Generate draft
const draft = await generateDraft(outline)

// Step 2: Self-critique
const critique = await llm({
  prompt: `Review this draft and list 5 ways to improve it:\n\n${draft}`
})

// Step 3: Rewrite with critique
const final = await llm({
  prompt: `Rewrite this draft addressing these issues:\n\n${critique}\n\nOriginal:\n${draft}`
})
```

**Result**: Higher quality output (but 2x slower and more expensive).

### 4. Temperature Tuning

Different phases need different creativity levels:

```typescript
// Research: Low temperature (factual)
const research = await llm({
  temperature: 0.3,
  prompt: researchPrompt
})

// Outline: Medium temperature (structured but creative)
const outline = await llm({
  temperature: 0.6,
  prompt: outlinePrompt
})

// Draft: Higher temperature (engaging prose)

  temperature: 0.8,
  prompt: draftPrompt

// QA: Low temperature (objective analysis)

  temperature: 0.3,
  prompt: qaPrompt
})
```

## Lessons Learned

### 1. **Structured Output > Prose**

Early on, we let GPT-5 output freeform text. It was inconsistent.

**Fix**: Force JSON output everywhere. Parse and validate.

### 2. **Research First, Generate Second**

We tried generating articles directly. They were shallow.

**Fix**: Separate research phase with Exa. Feed research into generation.

### 3. **Confidence Scores Prevent Hallucinations**

GPT-5 will confidently state false information.

**Fix**: Make it rate its own confidence. Reject low-confidence claims.

### 4. **Few-Shot Examples > Long Instructions**

We had 2000-word prompt instructions. GPT-5 ignored them.

**Fix**: 2-3 example articles in the prompt. GPT-5 mimics perfectly.

### 5. **QA Phase is Non-Negotiable**

We tried skipping QA to save cost. Content quality tanked.

**Fix**: Always run QA. The $0.02 cost is worth it.
